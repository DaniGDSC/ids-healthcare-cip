System Architecture

Healthcare IoMT Intrusion Detection — thesis-grade pipeline from raw packet captures through detection, risk scoring, explanation, response generation, and operator-facing presentation. Built around two contributions (C1: dual-track detection, C2: role-adaptive MVE) and a C3 invariant (no-auto-execution, audit-first, no-silent-suppression).

Pipeline overview

Seven modules in a directed flow. Modules 0–1 are run once per dataset; Modules 2–5 are orchestrated by run_all_modules.py (starts at Module 2); Module 6 is the Streamlit dashboard that consumes everything downstream. Each card shows the module's path, role, primary inputs, and outputs.

Audit chain

C3 invariant: no auto-execution, audit-first, no silent suppression. Every operator action and every system event flows through a three-sink fan-out. The signed chain is the trust anchor for thesis defense and any future regulatory review.

Triple-sink fan-out (single capture_interaction() call → 3 writes)

sink 1 · buffered
online_interactions.jsonl
Flat per-interaction log, buffered with _FLUSH_AFTER = 10. Owner: _online_writer (AuditTrailWriter instance at module6_app.py:403). Optimized for high-frequency render events; not the trust anchor.
sink 2 · hash-chained
audit_trail.jsonl
SHA-256 hash-chained append-only log via AuditTrailWriter (module6_app.py:353). Each record carries prev_hash + integrity_hash — tampering is detectable on replay.
sink 3 · ECDSA-P256 signed
audit_log.jsonl
HardenedAuditLogger in module5_responses/module5_pipeline.py. Each entry signed with the project's ECDSA-P256 key (results/reports/audit_signing_key.pub.pem). Reviewer attribution bound from st.session_state["participant_id"] / ["sim_role"]. The trust anchor.

Defense-grade invariants

Properties that hold across the whole pipeline. Each is enforced in code and verifiable from the artifacts alone — no human attestation required.

InvariantEnforcement
Frozen test + demo split_metadata.yaml declares the invariant; Module 1 writes 4 disjoint parquets; test_split_contract.py re-validates on every CI run; Module 2 (future work) refuses to load demo_phase1.parquet via _assert_no_demo_leakage.
Deterministic split random_state=42 validated against canonical allowlist {0, 7, 42} by Phase1Config._random_state_canonical. WARN on deviation. Stratification on Attack Category (multi-class), not binary Label.
Hash-chained audit Every operator action through capture_interaction() fans out to 3 sinks; sink 3 is ECDSA-P256 signed with reviewer attribution. Tampering on any sink is detectable; the signed chain is unforgeable without the private key.
No auto-execution Dashboard exposes Acknowledge / Escalate / Dismiss buttons; none execute network or device actions. The clinical-constraint field in every MVE Layer 3 starts with "DO NOT" for CRITICAL/HIGH/MEDIUM alerts — enforced in mve_generator.py by the system prompt and rule-based templates alike.
No silent suppression Dismiss flow is gated by a required-rationale modal (_dismiss_dialog in module6_app.py). Empty rationale → st.error + early return without writing. Every dismissal is signed with category + rationale in the audit log.
TOCTOU-safe ingest Module 1's _ingest_with_integrity() hashes and parses each CSV from the same in-memory bytes — no re-open between hash and read. Multi-file bypass closed: every CSV in the input dir is hashed against the signed baseline.
p95 latency < 150 ms (Module 4 online) Recorded in online_latency_profile.json; surfaced in the dashboard's status strip. Per-stage breakdown (DAE / TreeSHAP / MVE) lets you defend the SLA bound during viva.
Role-adaptive MVE (C2) Three render functions in module6_app.py: render_analyst (L633), render_clinician (L677), render_admin (L713). Same alert, different surface: SOC sees SHAP top-features + DAE indicators; Clinician sees plain- language summary + patient-safety note; Admin sees aggregate tier breakdown.
