System Architecture

Healthcare IoMT Intrusion Detection — thesis-grade pipeline from raw packet captures through detection, risk scoring, explanation, response generation, and operator-facing presentation. Built around two contributions (C1: dual-track detection, C2: role-adaptive MVE) and a C3 invariant (no-auto-execution, audit-first, no-silent-suppression). Sprints 4–6 added the faithfulness/actionability upgrade: formula v2 (2-layer detect×context), counterfactual explanations, stability bands, role-mismatch routing, and an artifact schema-version chain.

Pipeline overview

Seven modules in a directed flow. Modules 0–1 are run once per dataset; Modules 2–5 are orchestrated by run_all_modules.py (starts at Module 2); Module 6 is the Streamlit dashboard that consumes everything downstream. Each card shows the module's path, role, primary inputs, and outputs.

cross-cutting · inference
Detection engine (Track A + DAE fusion)
detection_engine/ owns the cascaded inference path. DetectionEngine.build_augmented(X) is the only place that constructs [raw_features || Track_A_probas] — defined by common/dae_input.TRACK_A_FOR_DAE (currently ("xgboost",)) — and asserts the trained DAE's expected input width matches. predict(X) returns Track A probas (all 3), preds, c_track_a, c_track_b, fused c_detect = max(c_track_a, c_track_b), and the augmented matrix. Modules 3, 4, and 6 call into it instead of reimplementing fusion. Stale DAE artifacts fail loudly here, not inside a numpy broadcast 100 lines downstream.
cross-cutting · security
Signed integrity + path validation
module0_analysis/security.py provides IntegrityVerifier (signed SHA-256 baseline; refuses to run without one), PathValidator (workspace containment), ColumnAllowlist, and log_phase0_event (routes audit events into Module 5's signed chain). Module 1 uses these inline at ingest with a TOCTOU-safe single-pass hash-and-parse.
cross-cutting · audit
Hash-chained audit fan-out
Three sinks per operator action: online_interactions.jsonl (buffered), audit_trail.jsonl (hash-chained), audit_log.jsonl (ECDSA P256 signed). HardenedAuditLogger in module5_responses/module5_pipeline.py is the single authority; Module 6 routes through it on every dashboard click.
cross-cutting · standalone
Operational simulators
Top-level scripts run outside the orchestrator: drift_detection.py (PSI / KS over temporal stream), dynamic_threshold_sim.py (static vs adaptive thresholds), feedback_loop_demo.py (closed-loop AUROC reweighting), plus tools/build_simulation_stream.py (temporal replay stream) and tools/phase4_round2_simulator.py (RQ2 round-2 SHAP stability). Outputs feed Module 6's System Health panels.
cross-cutting · contracts
Artifact schema versioning (Sprint 6)
common/artifact_versioning.py is the single source of truth for the expected _schema_version on every artifact under results/ — producers stamp at write time, consumers verify at load time, mismatches raise ArtifactVersionMismatch (or route through a migration function in artifact_versioning_migrations). tools/version_gate.py sweeps the registry in CI and writes results/version_gate.json. Catches the "silent contract drift" class of bugs that previously surfaced as obscure numpy broadcast errors three modules downstream.

Audit chain

C3 invariant: no auto-execution, audit-first, no silent suppression. Every operator action and every system event flows through a three-sink fan-out. The signed chain is the trust anchor for thesis defense and any future regulatory review.

Triple-sink fan-out (single capture_interaction() call → 3 writes)

sink 1 · buffered
online_interactions.jsonl
Flat per-interaction log, buffered with _FLUSH_AFTER = 10. Owner: _online_writer (AuditTrailWriter instance at module6_app.py:477). Optimized for high-frequency render events; not the trust anchor.
sink 2 · hash-chained
audit_trail.jsonl
SHA-256 hash-chained append-only log via AuditTrailWriter (module6_app.py:427). Each record carries prev_hash + integrity_hash — tampering is detectable on replay.
sink 3 · ECDSA-P256 signed
audit_log.jsonl
HardenedAuditLogger in module5_responses/module5_pipeline.py. Each entry signed with the project's ECDSA-P256 key (results/reports/audit_signing_key.pub.pem). Reviewer attribution bound from st.session_state["participant_id"] / ["sim_role"]. The trust anchor.

Quality gates & CI

Four read-only gates run in CI after the regen tools finish. Each writes a machine-readable report under results/ and exits non-zero on failure — no human attestation required.

Gate fan-out (independent, runnable on demand)

gate 1 · faithfulness
faithfulness_gate.py
5 checks: narrative_faithfulness ≥ 0.85, perturbation faithfulness (F1 drop > 5% when top-5 SHAP masked), counterfactual_actionable_feasible ≥ 0.80 on M+H+C, stability unstable_share ≤ 0.60, fragile_share ≤ 0.90. Floors versioned in the script. Report: results/faithfulness_gate.json.
gate 2 · schema versions
version_gate.py
Walks ARTIFACT_VERSIONS registry in common/artifact_versioning.py; verifies each artifact's on-disk _schema_version matches the registered current version. Skips artifacts pending migration; fails the build on stale or unknown versions. Report: results/version_gate.json.
gate 3 · MITRE coverage
coverage_audit.py
Cross-checks attack categories present in alert_responses.json against the mapping in config/attack_to_mitre_mapping.yaml; confirms every routed alert has at least one MITRE ATT&CK technique. Reports: results/coverage_audit{,_demo}.json.
gate 4 · phase-0 baseline
phase0_baseline.py
Snapshots the three Phase-0 metrics (narrative_faithfulness, action_specificity, counterfactual_coverage) over the current artifacts. Not a fail-the-build gate; provides the baseline that later phases lift against. Report: results/phase0_baseline.json.

Defense-grade invariants

Properties that hold across the whole pipeline. Each is enforced in code and verifiable from the artifacts alone — no human attestation required.

InvariantEnforcement
Frozen test + demo split_metadata.yaml declares the invariant; Module 1 writes 4 disjoint parquets; test_split_contract.py re-validates on every CI run; Module 2 (future work) refuses to load demo_phase1.parquet via _assert_no_demo_leakage.
Deterministic split random_state=42 validated against canonical allowlist {0, 7, 42} by Phase1Config._random_state_canonical. WARN on deviation. Stratification on Attack Category (multi-class), not binary Label.
Hash-chained audit Every operator action through capture_interaction() fans out to 3 sinks; sink 3 is ECDSA-P256 signed with reviewer attribution. Tampering on any sink is detectable; the signed chain is unforgeable without the private key.
No auto-execution Dashboard exposes Acknowledge / Escalate / Dismiss buttons; none execute network or device actions. The clinical-constraint field in every MVE Layer 3 starts with "DO NOT" for CRITICAL/HIGH/MEDIUM alerts — enforced in mve_generator.py by the system prompt and rule-based templates alike.
No silent suppression Dismiss flow is gated by a required-rationale modal (_dismiss_dialog in module6_app.py). Empty rationale → st.error + early return without writing. Every dismissal is signed with category + rationale in the audit log.
TOCTOU-safe ingest Module 1's _ingest_with_integrity() hashes and parses each CSV from the same in-memory bytes — no re-open between hash and read. Multi-file bypass closed: every CSV in the input dir is hashed against the signed baseline.
p95 latency < 150 ms (Module 4 online) Recorded in online_latency_profile.json; surfaced in the dashboard's status strip. Per-stage breakdown (DAE / TreeSHAP / MVE) lets you defend the SLA bound during viva.
Role-adaptive MVE (C2) Three render functions in module6_app.py: render_analyst (L711), render_clinician (L791), render_admin (L834). Same alert, different surface: SOC sees SHAP top-features + DAE indicators; Clinician sees plain- language summary + patient-safety note; Admin sees aggregate tier breakdown.
Detection gates emission (formula v2) Module 3 v2 formula is multiplicative — R = C_detect × (1 + αD_crit + βS_data + γA_patient) — and MIN_DETECTION_GATE in module3_risk_scoring/config.py forces NORMAL whenever C_detect is below the gate. Eliminates the v1 failure mode where idle-but-critical devices triggered LOW alerts at R ≈ 0.21 with zero detector signal (see docs/formula_v2_rationale.md).
Stability-gated auto-execute module4_explanations/stability.py attaches a band (STABLE / BORDERLINE / UNSTABLE) from top-K Jaccard under Gaussian noise. module5_responses/adaptive.py demotes auto_execute on BORDERLINE/UNSTABLE. faithfulness_gate fails the build if the unstable share exceeds 60% or the fragile share exceeds 90%.
Counterfactual feasibility floor Every M+H+C alert carries a counterfactual payload (module4_explanations/counterfactual.py). The CI gate requires counterfactual_actionable_feasible ≥ 0.80; currently at 0.81. Sparsity preference (1 → 2 → 3 feature edits) makes the explanation actionable for non-ML users.
Role-routing mismatch surfaced module5_responses/role_routing.py compares the SHAP top-category's expected primary role against ATTACK_ROUTING's assignment; mismatches attach a RoutingWarning on the response record, which the dashboard surfaces as a one-click reroute button.
Artifact schema versions enforced Every artifact under results/ carries _schema_version (top-level or in _provenance). common/artifact_versioning.py is the registry; tools/version_gate.py sweeps it in CI and refuses the build on stale, missing, or unknown versions. Catches "silent contract drift" before it surfaces as a downstream numpy broadcast error.
Narrative faithfulness floor phase0_metrics.narrative_faithfulness — P(clinician narrative top-1 category == SHAP top-1 category) on xgboost — must stay ≥ 0.85. Last recorded: 0.9674 over n=307 (results/phase0_baseline.json).
