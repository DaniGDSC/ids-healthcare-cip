Composite formula assembly
  1. Per-alert run all 4 models (3 Track A + DAE) on the alert's feature vector — get 4 probabilities/scores.
  2. C_detect — fused detector signal (consensus across XGBoost/RF/DT/DAE). C_track_a + C_track_b retained as ancillary diagnostics in risk_components.
  3. D_crit — device criticality from device-tier lookup (default: vital_monitoring for WUSTL-EHMS).
  4. S_data — data sensitivity (binary biometric exposure / PHI scope).
  5. D_clinical_tier — clinical-tier weight (active-care context).
  6. Composite R clamped to [0, 1]; mapped to tier via boundaries 0.40 / 0.60 / 0.80.

Per-alert 6-stage explanation pipeline (online)
  1. Predict — 4-vote Track-A + cascaded-DAE (augmented with Track-A probas).
  2. Severity — n_flagged: ≥4 CRIT, 3 HIGH, 2 MED, ≤1 LOW. LOW short-circuits.
  3. TreeSHAP — top-3 per model via np.argpartition (O(F)); RandomForest skipped (90% of treeshap_ms baseline).
  4. DAE decompose — top-3 per-feature reconstruction error (reused from Step 1 forward pass).
  5. NLG — clinician_summary via templates + feature-category narratives.
  6. Risk decompose — flagging_models, confidence spread, dae_contributes.
  7. MVE 3-layer — generated by src/mve_generator.py with shap_context input. Layer 3 starts with "DO NOT" for CRITICAL/HIGH/MEDIUM (clinical-constraint invariant).
  8. Response policy — escalation chain (Biomed → Security → Charge Nurse for IoMT critical); max_response_min; clinical-constraint text; rationale.

Composite risk formula

Module 3 reduces the per-alert ML output + device + clinical context into a single composite risk score in [0, 1] and maps it to a 4-tier label.

R = w1·Cdetect + w2·Dcrit + w3·Sdata + w4·Dclinical_tier
Cdetect
w₁ = 0.40
Fused detector signal (consensus across 3 Track-A models + cascaded DAE). Highest weight — primary ML signal.
Dcrit
w₂ = 0.25
Device criticality — life-sustaining (ventilator/infusion pump) = 1.0; vital monitoring = 0.85; clinical-support = 0.6; admin = 0.25.
Sdata
w₃ = 0.15
Data sensitivity — PHI exposure scope of the alert. Lowest weight: a network-only signal without PHI scope is still actionable.
Dclinical_tier
w₄ = 0.20
Clinical-tier weight — captures the device's active-care context (life-sustaining / vital-monitoring / diagnostic / auxiliary) as a per-alert clinical-impact multiplier.
Tier boundaries
LOW · R<0.40
MEDIUM · 0.40–0.60
HIGH · 0.60–0.80
CRITICAL · ≥0.80

Data invariants

Properties verifiable from the data alone — no test runs required, no human attestation. Each is enforced in code at the point where it could otherwise be violated.

Test & demo are frozen
split_metadata.yaml · invariants block
No model sees test_phase1.parquet or demo_phase1.parquet during training. Enforced by: (a) Module 2 reads train_phase1 + benign_only, never test/demo; (b) _assert_no_demo_leakage guard in Module 2 raises RuntimeError on any read of demo_phase1.parquet.
Splits are disjoint
tests/test_split_contract.py · test_splits_disjoint_by_row_count
train ∩ val ∩ test ∩ demo = ∅. Verified by row-count sum = n_total exactly. The splitter uses sequential StratifiedShuffleSplit on disjoint pools, so set disjointness is structurally guaranteed.
Stratification ≤ ±2%
stratify="Attack Category" · multi-class
Spoofing, Data Alteration, normal counts preserved within ±2% across all 4 splits. Stratification is on the multi-class label, not the binary one — binary stratify would have skewed Spoofing vs Data Alteration proportions.
Deterministic via random_state
Phase1Config._random_state_canonical
random_state ∈ {0, 7, 42} canonical allowlist. Anything else triggers a WARN (research-integrity signal: an attacker who can edit the YAML cannot pin to a favourable seed silently).
TOCTOU-safe ingest
module1_preprocessing/phase1/pipeline.py · _ingest_with_integrity
Each raw CSV is hashed AND parsed from the same in-memory bytes. Closes the TOCTOU window where a previous flow hashed one file then re-opened it for pd.read_csv. Multi-file bypass also closed: every CSV in the input dir gets hashed.
No identifier features survive Stage 1
HIPAASanitizer · identifier_removal.remove_columns
MAC + IP addresses, sequential indices dropped before any modelling. SrcMac in particular perfectly separated normal/attack in the raw labels — a leakage source flagged in the dataset README and removed at Stage 1.
Fit-on-train scaling
RobustScalerTransformer.scale_both
Scaler fits only on X_train; val / test / demo are transformed but never seen by the fit. Median + IQR chosen over StandardScaler because Phase 0 EDA flagged heavy-tailed distributions.
Signed model pickles
common.model_registry · loads_signed
Every Track-A classifier pickle is ECDSA-P256 signed at training time. Module 4 / 6 refuse to load unsigned or tampered pickles — closes the pickle-RCE attack surface.
Composite weights sum to 1.0
module3_risk_scoring · WEIGHTS · _ratios_sum_to_one
w₁ + w₂ + w₃ + w₄ = 0.40 + 0.25 + 0.15 + 0.20 = 1.00. Composite R is therefore bounded in [0, 1] when each component is in [0, 1], which the tier-mapping logic at 0.40 / 0.60 / 0.80 assumes.
Layer-3 MVE starts with "DO NOT"
src/mve_generator.py · system prompt + rule-based templates
For CRITICAL/HIGH/MEDIUM alerts, the MVE's clinical-constraint field MUST start with "DO NOT" — preventing the LLM from recommending a clinical action that could harm a patient. The rule-based templates enforce this structurally; the LLM system prompt enforces it via instruction + post-validation.
Hash-chained audit fan-out
HardenedAuditLogger · capture_interaction
Every operator action writes to 3 sinks. Sink 3 (audit_log.jsonl) is ECDSA-P256 signed with prev_hash chaining — tampering is detectable on replay; the signed chain is unforgeable without the private key.
Dashboard test-only filter
module6_evaluation/module6_app.py · _TEST_SPLIT_OFFSET
Triage view filters alert_responses.json to sample_index ≥ 2,448, displaying only test-split alerts to operators. Prevents val-set data (used for hyperparameter tuning) from leaking into the operator-facing queue.
