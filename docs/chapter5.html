Metric definitions (as implemented)

FNRcritical — tools/rq1_compute_metrics.py:107-111:

crit_device_mask = d_crit >= CRITICAL_DEVICE_THRESHOLD   # 0.8
crit_attack_mask = crit_device_mask & (y_true == 1)
n_crit_attacks = int(crit_attack_mask.sum())
n_crit_attacks_surfaced = int((crit_attack_mask & surfaced_mask).sum())
fnr_critical = (n_crit_attacks - n_crit_attacks_surfaced) / n_crit_attacks

Surfaced tiers: ("MEDIUM", "HIGH", "CRITICAL"). Target = 0.05 (rq1_compute_metrics.py:126). Labelled "primary_safety_metric" in the JSON (line 124) and is the selection objective for weight sensitivity (lines 474-475).

F2 — tools/rq1_compute_metrics.py:63-64:

f2 = 5 * prec * rec / (4 * prec + rec)   # closed form of F-β with β=2

Threshold selection uses the same β=2 via module2_detection/models/_threshold.py:29-69 (precision_recall_curve vectorised, default beta=2.0), called by every Track A detector through _base_detector.py:235-241.

Nuance for the thesis: FNRcritical is the primary safety gate; F2 is the threshold-selection objective. The two roles must not be conflated in §5.1's prose.

User-study design — A/B counterbalancing

Implementation: module6_evaluation/module6_app.py:539-568. Seed line (:547):

seed = int(hashlib.md5(participant_id.encode()).hexdigest(), 16) % (2**31)

Latin-square block order by PID parity; balanced True/False blocks; shuffle within each block. MD5 seed confirmed.

N participants: 25 per arm — recorded independently in survey/m5_result.yaml:9-10 and analysis/outputs/rq3_primary.json:40,52. survey/result/ contains 50 per-participant files (P01–P25 × A/B), consistent with a within-subjects design.

The two artifacts compute the same field name under two different definitions:
