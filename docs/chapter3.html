Section 3.2

Detection Layer

Status summary. Track A (3 classifiers) and Track B (DAE benign-only) are real and tested; fusion is the single line c_detect = max(c_track_a, c_track_b). The 4-class fusion taxonomy (KNOWN_ATTACK / NOVEL_ANOMALY / CONFIRMED_ANOMALY / BENIGN) and the a_high / a_low / b calibration thresholds claimed in the outline do not exist in code. The EA-06 BENIGN_MEDIAN imputation + OK/IMPUTED_NAN/DEGRADED/ FAILED data-quality flag scheme does not exist in code. The elevation-only invariant exists by construction (max-fusion) but has no dedicated test.

Verified facts

  • Track A trains 3 classifiers: TRACK_A_MODELS = {xgboost, random_forest, decision_tree} — module2_detection/module2_train_models.py:202-221.
  • "XGBoost" is sklearn GradientBoostingClassifier, not the xgboost library. XGBoostDetector = GradientBoostingDetector — module2_detection/models/XGBoost.py:18. Docstring: "This class wraps sklearn's GradientBoostingClassifier as an XGBoost-equivalent surrogate." — module2_detection/models/GradientBoosting.py:3-7.
  • XGBoost is the production decision driver: PRIMARY_TRACK_A = "xgboost" — detection_engine/engine.py:90. Engine docstring at engine.py:4-11 confirms RF/DT exist for analyst-report consensus only, not fusion.
  • Only XGBoost feeds the cascaded DAE input: TRACK_A_FOR_DAE = ("xgboost",) at common/dae_input.py:15.
  • DAE on benign-only: benign_mask = y_train == 0; X_benign = X_train[benign_mask] — module2_detection/dae_training.py:89-90. DAEDetector.fit(X_benign, …) docstring asserts "y=0 only" — module2_detection/models/DAE.py:243-256.
  • DAE architecture in code: Input → Dropout(noise_rate) → Dense(encoder, relu) → Dense(bottleneck, relu) → Dense(decoder, relu) → Dense(n_features, sigmoid); loss mse; bottleneck < n_features asserted. — module2_detection/models/DAE.py:201-237. Defaults: encoding_dims=[16, 8, 16], noise_rate=0.1 — DAE.py:91-92.
  • Cascade gate: rows with XGBoost proba ≥ TAU_SKIP_DAE = 0.90 skip the DAE forward pass and get c_track_b = 0. — detection_engine/engine.py:100, 260-270. Compute-side optimisation, explicitly not a decision boundary.
  • Fusion: one line — c_detect = np.clip(np.maximum(c_track_a, c_track_b), 0.0, 1.0) at detection_engine/engine.py:283. Comment immediately above: "Fusion: DAE elevates, never suppresses Track A" — engine.py:282.

Code ↔ outline discrepancies

Fusion taxonomy

Outline claims 4 fusion classes (KNOWN_ATTACK / NOVEL_ANOMALY / CONFIRMED_ANOMALY / BENIGN) with a_high / a_low / b thresholds.
