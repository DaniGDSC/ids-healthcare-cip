## 3 Research Questions (Refined for Clinical IoMT) & Required Outputs

Based on your system’s architecture and the clinical environment (patient safety, alert fatigue, device criticality), here are the **refined RQs** and the **minimum set of outputs** that fully answer each RQ.

---

### RQ1 (Architecture Integration)

**How does the system integrate risk‑adaptive scoring, explainable MVE (3‑layer), and closed‑loop response recommendations into a unified, clinically safe architecture?**

**Required outputs (evidence):**

| Output | Format | Location / Content |
|--------|--------|---------------------|
| System architecture diagram | Image (PNG/Mermaid) | Shows modules 0–6, data flow from raw dataset to `evaluation_alerts.json`, and how dashboard reads it. |
| Module description table | Markdown/PDF | Lists each module (0–6), input/output files, key functions, and clinical invariants (e.g., “Track B only elevates”, “no auto‑execution”). |
| Source code excerpts | Code snippets | `run_all_modules.py` execution order, `module3_risk_scores.py` composite risk formula, `src/risk_scorer.py` adaptive gate logic, `src/mve_generator.py` rule‑based fallback. |
| Demonstration of offline‑first fallback | Test result | Run dashboard without API keys – verify MVE still shows (rule‑based Mode B). |
| Invariant verification log | Commands output | `grep` results showing no `subprocess.run` or `iptables` in response modules; `max` fusion in risk scoring. |

**Success criteria:** All modules are documented, data flow is traceable, invariants hold, and the architecture is clearly clinically motivated (e.g., never suppresses critical devices).

---

### RQ2 (Performance & Safe Failure)

**Does the risk‑adaptive scoring achieve FNR_CRITICAL ≤ 5%, keep the CRITICAL alert rate ≤ 10% (under realistic test sets), and maintain safe failure behaviour under 5+ failure modes?**

**Required outputs (evidence):**

| Output | Format | Location / Content |
|--------|--------|---------------------|
| `evaluation_alerts.json` | JSON file | Must contain: `true_severity`, `risk_level`, `should_surface`, `adjusted_score`, `threshold`, `risk_multiplier`, `device_criticality`, `device_patchable`. |
| `rq2_metrics.json` | JSON file | Generated by `compute_rq2_metrics.py`. Includes `fnr_critical`, `critical_alert_rate`, `sensitivity`, `specificity`, confusion matrix. |
| Safe failure tests | Python file | `tests/test_safe_failure.py` with ≥5 test functions, each simulating a failure (missing context, unknown device, SHAP timeout, etc.) and asserting safe behaviour (e.g., `should_surface=True` or risk multiplier increased). |
| Test run log | Console output | `pytest tests/test_safe_failure.py -v` showing all tests PASS. |
| Explanation of high critical_alert_rate (if present) | Report paragraph | Clarify that the curated evaluation set is stress‑test (15/20 true critical), not a deployment statistic. Also report the rate on a random sample (≤ 10%) if available. |

**Success criteria:** `fnr_critical ≤ 0.05`, `critical_alert_rate ≤ 0.10` (on a representative test set), all safe failure tests pass.

### RQ3 (Human‑in‑the‑Loop)

**Does the MVE 3‑layer explanation improve decision accuracy, reduce over‑reaction and under‑reaction, increase user trust, and speed up response times compared to a baseline (no explanation)?**

**Required outputs (evidence):**

| Output | Format | Location / Content |
|--------|--------|---------------------|
| Study mode implementation | Source code | `module6_app.py` study mode, `study_loader.py`, `assign_ab_condition()`, checkpoint logic, response schema. |
| Participant responses repository | JSON files | `results/reports/study_responses_*.json` for at least 10 participants. Each record contains all HITL fields (`participant_id`, `condition`, `chosen_severity`, `correct_severity`, `confidence`, `decision_time_sec`, `composite_score`, etc.). |
| RQ3 analysis script | Python file | `analysis/analyze_rq3.py` – loads responses, computes accuracy, over/under‑reaction, trust, response time, Wilcoxon p‑values. |
| Analysis outputs | Table + plots | `analysis/plots/accuracy_by_condition.png`, `reaction_rates.png`, `confidence_boxplot.png`, `response_time_boxplot.png`. Also a table of mean values and p‑values. |
| Statistical significance report | Terminal output / PDF | Paired t‑test or Wilcoxon results showing that MVE significantly (p < 0.05) improves accuracy, reduces both reaction errors, increases confidence, and reduces response time. |

**Success criteria:** All metrics favour MVE with p < 0.05; no trade‑off (over‑reaction and under‑reaction both decrease). Response time may decrease or remain similar.
