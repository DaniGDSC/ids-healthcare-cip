Component Architecture

Module Details

Each module is a self-contained pipeline stage with defined inputs, outputs, and contracts.

📊

Module 0 — EDA

Descriptive stats, class distribution analysis, correlation matrix, data quality & reproducibility reports. SHA-256 recorded for audit.

Offline 8 sub-files
🧹

Module 1 — Preprocessing

HIPAA identifier removal, encoding, missing value handling, variance/correlation filtering, stratified split, RobustScaler, SMOTE.

Offline Leakage barrier
🤖

Module 2 — Detection

Dual-track: Track A (XGBoost/RF/DT supervised) + Track B (DAE novelty, benign-only). Max-fusion ensures Track B only elevates scores.

Offline 5 serialized models
⚖️

Module 3 — Risk Scoring

Composite risk: R = w₁·C_detect + w₂·D_crit + w₃·S_data + w₄·A_patient. Risk-adaptive gate with patchability-aware thresholds.

Online Suppression gate
🔍

Module 4 — SHAP Explainer

TreeSHAP on XGBoost, maps features to 8 clinical groups. Outputs SHAPContext with top_category, top_features, confidence. Only when surfaced.

Online 8 feature groups
📝

MVE Generator

3-layer clinical explanation (WHY/SEVERITY/ACTION). Mode A: LLM (Anthropic). Mode B: rule-based templates. ≤150 words, no SHAP exposed.

Online 5 alert types
🚨

Module 5 — Response Engine

PolicyEngine with clinical safety override, simulated ActionExecutor, NotificationService, immutable JSONL audit log, feedback-loop stub.

Online Human-in-loop
✅

Module 6 — Evaluation

M1–M8 acceptance tests, 6 negative boundary tests, A/B study analysis. Streamlit app with 3 roles × 3 modes for human evaluation.

Evaluation Streamlit UI
MVE Output Structure

Minimum Viable Explanation Demo

Example output for a T5 IoMT behavioral deviation alert on a BD Alaris infusion pump.

LAYER 1 — WHY ANOMALOUS (≤60 words)
Baseline Behavior
BD Alaris infusion pump (ICU-3A) normally communicates with pharmacy controller using HTTPS.
Deviation Description
Starting 02:14, device initiated DNS to 203.0.113.99 at abnormal frequency, outside established baseline. Normal: 12 queries/min. Observed: 310 queries/min (25.8x above baseline).
Confidence Indicator
Confidence: HIGH — strong anomaly signal with 90-day baseline
≈ 52 words
LAYER 2 — CLINICAL SEVERITY (≤50 words)
Affected System
BD Alaris infusion pump (ICU-3A) — medication delivery
Patient Care Impact
Compromise could alter medication dosage or interrupt drug delivery. Active infusion therapy at risk.
PHI Exposure
Real-time patient vitals and identifiers for ICU-3A census at risk.
Severity
CRITICAL — Life-sustaining system actively supporting patient care.
≈ 43 words
LAYER 3 — RECOMMENDED ACTION (≤60 words)
Immediate Action
If no maintenance: block anomalous port at switch for 10.1.3.45.
Clinical Constraint
DO NOT power off or physically disconnect infusion_pump. Switch-port block is SAFE. Contact Biomed Engineering first.
Escalation Path
(1) Biomed Engineering on-call, (2) Security lead, (3) ICU/floor charge nurse.
Timeframe
Act within 15 minutes. Preserve network logs from the past 30 minutes.
≈ 55 words · Total: ≈ 150 words
Clinical Severity Mapping

Severity Levels (Clinical, Not CVSS)

Severity is mapped to patient care impact — not vulnerability scores.

CRITICAL
Life-sustaining systems

Ventilators, active infusion pumps, surgical equipment

⏱ Respond immediately

HIGH
Active clinical care

EHR, active PACS, pharmacy systems, patient monitors

⏱ Within 1 hour

MEDIUM
Clinical-support (not immediate)

Scheduling, archived imaging, laboratory information

⏱ Within 4 hours

LOW
Administrative, minimal PHI

Guest Wi-Fi, marketing systems, scheduling

⏱ Within 24 hours

Key Design Invariants

1
Track B only elevates — DAE reconstruction error can only increase the fused anomaly score, never suppress it
2
Suppression at Module 3 only — risk gate is the single point where alerts are filtered; MVE Generator is never called on suppressed alerts
3
Human-in-the-loop mandatory — system recommends actions, never auto-executes blocking or isolation
4
No model internals exposed — SHAP values must not appear in user-facing MVE text
5
Clinical severity over CVSS — system uses CRITICAL/HIGH/MEDIUM/LOW mapped to patient care impact
6
Offline-first — all tests must pass without API keys (Mode B rule-based fallback)
